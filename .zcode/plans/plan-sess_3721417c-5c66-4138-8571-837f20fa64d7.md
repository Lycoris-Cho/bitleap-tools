# 歌单功能（免登录）实施方案

## 一、范围（按你的四个选择）

**做**：推荐歌单（每天变）→ 分类浏览（70 个分类）→ 歌单详情（完整曲目、分页）→「播放全部」替换队列 / 「加入队列」追加 → 顶栏「随机」（原「每日推荐」改名）+ 新增「发现」入口。
**不做**：登录态相关内容（每日推荐歌曲、我喜欢的音乐、我的歌单）——需要 MUSIC_U cookie，留下期。

## 二、接口层（已逐个探活，全部免登录）

新增两个 route，沿用现有 `{code, data}` 约定 + `cache: 'no-store'` + 现有 `NETEASE_HEADERS`，上游地址集中写在这两个文件里，方便日后替换：

**`src/app/api/wangyi-playlists/route.ts`** — 歌单发现（`?type=` 三合一）
- `type=recommend&limit=12` → `music.163.com/api/personalized/playlist` → 推荐歌单（每天更新）
- `type=category&cat=华语&limit=30&offset=0` → `/api/playlist/list?order=hot` → 该分类歌单 + `total/more`
- `type=catalogue` → `/api/playlist/catalogue` → 70 个分类名 + 五组分组（语种/风格/场景/情感/主题）
- 统一映射成 `PlaylistBrief { id, name, cover, playCount, trackCount, copywriter? }`

**`src/app/api/wangyi-playlist/route.ts`** — 歌单详情（`?id=&limit=100&offset=0`）
- `/api/v6/playlist/detail?id=` 拿头部信息（名称/封面/简介/创建者/播放量/trackCount）+ `trackIds`（全部，例：125 个）+ 前 10 首带封面元数据
- 其余曲目按 `offset/limit` 切片，分批（≤100 个 id）请求 `/api/song/detail?ids=[…]` 补元数据（并行两三次，避免 URL 过长与上游限流）
- 返回 `{ playlist, tracks: PlaylistTrack[], total, hasMore }`

> 已确认死掉的接口（`/api/top/playlist`、`/api/playlist/track/all` 均 404）不走；`/api/song/detail` 正是项目里已有的兜底接口，形状一致。

## 三、数据流：歌单怎么变成能播的队列（几乎不动播放逻辑）

歌单曲目只有 id 没有直链。而现有队列已有 `isUrlStale`（`url` 为空或超过 10 分钟即视为陈旧），`switchTo()` 会在切歌时自动重新解析直链。所以：

```
PlaylistTrack → toMusicResult() → { id, name, artist, album, cover, duration, url: '', resolvedAt: 0 }
                 ↓ setQueue()
             队列就绪；播到哪首，switchTo 解析哪首（顺序播放天然只解析需要的那首）
```

- 「播放全部」= 用歌单曲目替换队列 + index 0 + 回播放视图；点某一首 = 同样替换但 index 指向它（与网易云一致）。
- 「加入队列」= 追加到队列末尾，不动当前 index；原队列为空时等价于播放全部。
- 解析失败（VIP/独家/下架）→ 提示「「xxx」暂不可播，已跳过」并自动跳下一首；歌单详情里能用 v6 的 `noCopyrightRcmd` 字段把不可播曲目灰显。
- 队列持久化天然兼容：读取时的过滤条件是 `typeof song.url === 'string'`，空串可以通过；刷新后点播放会重新解析。

## 六、实施顺序（每步可独立验收）

1. **接口层**：两个 route + 类型；用 dev server 实测推荐/分类/详情三个端点真能通并返回预期结构（先跑通再写 UI）。
2. **发现视图**：主区视图切换骨架 + 顶栏入口 + 推荐歌单 + 分类 + 网格（含骨架屏/错误态）。
3. **歌单详情**：头部 + 曲目分页 + 懒封面；接入「播放全部 / 加入队列 / 点某首从它开始」与不可播跳过。
4. **打磨**：进出场动画、hover 细节、三档断点（360/768/1280）不溢出、返回的 Esc 键、aria 标签。
5. **可选（先验端点再定）**：发现视图内搜索歌单（`/api/cloudsearch/get/web?type=1000`）与排行榜（`/api/toplist`）。

## 七、风险与降级

- 上游是老接口 + 第三方镜像，随时可能变（`/api/top/playlist` 已经 404 就是例子）：推荐失败→退到分类，分类失败→退到推荐，全挂→明确报错而不是白屏；上游路径集中，日后好换。
- 长歌单（1000+ 首）：默认 100 首分页、封面懒加载、元数据分批 ≤100 id。
- VIP/独家曲目：灰显 + 跳过 + 提示，不会卡住连播。
- 现有功能零影响：播放/歌词/两档动画/逐曲同步校准/队列/存档都不改逻辑，只在主区加一层视图切换。

## 八、验证方式

接口用 dev server 真实请求核对字段；UI 走真实数据（不再造假数据预览页）；用浏览器量网格列数、卡片尺寸、断点不溢出、点击链路（发现→歌单→播放全部→队列真的换掉且能播）。这个环境的浏览器看不到动效（rAF 被节流），所以**视觉观感仍需你亲眼过一遍**，我会把可量化的部分都量给你。
