## 二、动效系统：全部由**一个时间参数**驱动

关键决定：**不用 CSS keyframes，所有动效都是 `apply(t)` 的纯函数**。原因有三：
1. 拖进度条要能**逐帧回看**，CSS 动画没法 seek；
2. WebM 是逐帧渲染的，若常态动效走 CSS，它会按**真实墙钟**走，而视频时间按 1/30 秒/帧推进，录出来节奏全错；
3. 导出的 PNG 只要 `apply(入场结束时刻)` 就是**确定性的终态**，不需要像 BitLeap 那样再额外 reset 一遍（那条"防白图"的经验我照做，只是实现更干净）。

每帧只写 `transform` / `opacity`，约 150 次 style 写入（≈1~2ms），60fps 无压力。

### 入场（可拖拽、可录进视频）
| 参数 | 选项 |
|---|---|
| 位移方式 | 上浮 / 放大 / 横向滑入 |
| 出场顺序 | 主角先 / 由外向内 / 从左到右 |
| 错峰间隔 | 0~0.3s/人 |
| 时长 / 缓动 | 0.4~3s / 复用站点那套缓动（匀速·缓入·缓出·缓入缓出·强缓出·柔和）|
| 一起入场 | 标题（淡入 + 上移 + 字距收拢）、角色名条（跟人物之后）、装饰（网格/椭圆/条码/四角淡入）|

### 常态微动（循环，全部可选 + 强度可调）
呼吸（人物缩放/明暗）· 漂浮（上下浮）· **主角光晕呼吸** · **画面扫光**（斜向光带掠过）· **花瓣飘落**（数量/速度/颜色）· 浮尘闪烁 · 轨道椭圆缓转。

### 两个静态质感效果（顺手补上，很出片）
**双色调叠加**（给画框图叠一层主色，多张图更统一）· **颗粒质感**（SVG turbulence 噪点，站点里已有这个手法）。

### 动效预设
静雅（只有入场）/ 灵动（加呼吸+花瓣）/ 盛典（全套+扫光+光晕）/ 关闭 —— 一键切换，再手动微调。

## 三、播放控制

播放 / 暂停 · 重播 · **入场进度条（可拖）** · 预览倍速 0.5×/1×/1.5× · 入场循环播放（演示用）。默认跟随系统 `prefers-reduced-motion`：开了就不自动播，直接给终态。

## 四、WebM 动图导出

照你站点 `weiguang` 的先例（`MediaRecorder` + `canvas.captureStream`）：

- 面板：**时长** 2/3/5s · **分辨率** 720p/1080p（默认 720p）· **帧率** 30 · 是否包含入场
- 流程：隐藏 canvas → 逐帧 `apply(t)` + `html-to-image` 的 `toCanvas`（按目标分辨率设 pixelRatio，1:1 贴到录制 canvas）→ `track.requestFrame()` → `MediaRecorder(vp9)` → `.webm` 下载
- 带**进度条**与预估耗时（720p/3s ≈ 90 帧，约 4~6 秒）
- 生成前先预估并提示；**Safari / 微信里播放不了 webm**，这一点直接写在面板上
- PNG 导出保持不变（会先归位到终态，保证不缺内容）

## 六、验证（写完我会真跑）

1. `tsc` / `eslint` / `next build` 全过。
2. **时间线数学单测**：`t=0` 时所有元素都在入场起始态（人物不可见）；`t=入场结束` 时全部归位（transform 为恒等、opacity 为 1）；花瓣/浮尘的位置在 `t` 与 `t+周期` 时一致（循环无缝）；`apply` 是纯函数（同一 t 两次结果相同）。
3. **浏览器实测**：拖进度条 → 人物位移/透明度随之变化；播放 → 逐帧推进；换动效预设 → 参数与画面同步变化；`prefers-reduced-motion` 下不自动播。
4. **视频导出真伪**：跑一次录制，校验产出的 webm **非空**、mime 正确；并单独抓一帧 `toCanvas` 验证分辨率确实等于所选（720p → 1280×720）、内容非空。
5. **PNG 导出**：确认终态下导出不缺内容（沿用上次的 IHDR 校验法，同时抽查一张图的像素不是全透明/全白）。
6. 窄屏（<1280）两栏折叠成单栏时的顺序：海报在上、面板在下。
